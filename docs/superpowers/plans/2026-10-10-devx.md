# Devx: isolated dev offices, safe testing, CI end-to-end, agent skills

Date: 2026-10-10. Branch: `feature/devx`. Target: one PR against `main`.

## Why

Agentcy is developed mostly by coding agents, often several at once in separate git worktrees,
on a machine that also runs the owner's live office. Today:

- A second office cannot run next to the live one. `infra/docker-compose.yml` fixes the
  container names (`agent-office-*`), the ports (8065/3033/2222) and, implicitly, the compose
  project name (`infra`, from the directory). `src/cli/bootstrap.ts` hardcodes the container
  names in `docker exec` calls. `tmuxSession` and `opencodeBasePort` are fixed in the config.
- `office init|up|start|setup` from a second checkout would write a new `infra/.env` and
  `docker compose up -d` under the same project name, recreating the live containers on that
  checkout's empty `infra/data`.
- The integration tests are skipped in CI and, run locally, create bots in the live `#office`.
- Nothing exercises hire → wake → reply end to end.
- There are no dev commands, no linter, no tracked `CLAUDE.md`, no project skills, and a fresh
  worktree has no `node_modules`.

## Decisions (from the owner)

1. Isolated dev offices: yes. Must support several in parallel (one per checkout/worktree) and
   a fresh clone in a cloud coding session.
2. Guard rail that refuses to clobber another checkout's stack: yes.
3. End-to-end agent tests use a real, cheap opencode model. No fake harness.
4. Integration and end-to-end tests in CI: must have.
5. Dev commands: yes, plus project skills per architecture area, because agents do the work.
6. Repo hygiene: track `CLAUDE.md` and the research docs, bootstrap `node_modules` in new
   worktrees, add a linter.

Out of scope: `office doctor`, new debugging commands, a mass reformat of the codebase (two
other feature branches are in flight; a formatter config is added but not applied or enforced).

## Shared contract

Every work package below codes against this contract. It is the interface between them.

### Instance model

One office instance per checkout. `state/`, `workspaces/`, `brain/`, `office.config.json` and
`infra/.env` already live under the checkout root, so they are already per checkout. What is
added is isolation of the shared host resources, all driven by `infra/.env`:

| `infra/.env` key | Default when unset (the existing/live office) | Dev instance `<name>` |
|---|---|---|
| `OFFICE_INSTANCE` | unset: a normal office | `<name>`: marks a dev instance |
| `COMPOSE_PROJECT_NAME` | unset: compose uses `infra` | `agentcy-<name>` |
| `OFFICE_CONTAINER_PREFIX` | `agent-office` | `agentcy-<name>` |
| `MM_PORT` | `8065` | `<base>` |
| `FORGEJO_PORT` | `3033` | `<base>+1` |
| `FORGEJO_SSH_PORT` | `2222` | `<base>+2` |
| `MM_SITE_URL` | `http://127.0.0.1:8065` | `http://127.0.0.1:<base>` |
| `FORGEJO_ROOT_URL` | `http://127.0.0.1:3033/` | `http://127.0.0.1:<base+1>/` |
| `BIND_ADDR`, `POSTGRES_PASSWORD` | as today | `127.0.0.1`, random |

`<name>` is `<slug>-<hash6>`: the slug (below) plus the first 6 hex characters of
`sha1(realpath(checkout root))`, so two checkouts never share a name by accident.

The defaults must leave an existing office byte-for-byte unaffected: same project name, same
container names, same ports, same bind-mounted `infra/data`. `docker compose config` for a
checkout with today's `infra/.env` must render the same containers, ports and volumes as before.

`infra/docker-compose.yml` changes: `container_name: ${OFFICE_CONTAINER_PREFIX:-agent-office}-postgres`
(same for `-mattermost`, `-forgejo`), host ports `${MM_PORT:-8065}`, `${FORGEJO_PORT:-3033}`,
`${FORGEJO_SSH_PORT:-2222}`, network `name: ${OFFICE_CONTAINER_PREFIX:-agent-office}`.

New committed `infra/docker-compose.dev.yml`: an override that swaps every `./data/...` bind
mount for a named volume (declared top-level), so a dev instance leaves no root-owned files in
the checkout and `docker compose down -v` removes all its data. `composeFileArgs(root)` appends
it when `infra/.env` has `OFFICE_INSTANCE` (after the main file, before the LAN override).
For a dev instance `composeFileArgs` also emits an explicit `-p agentcy-<name>` derived from
`OFFICE_INSTANCE` (first in the argument list), so neither a missing `COMPOSE_PROJECT_NAME`
line nor a shell-exported one can ever make a dev command act on project `infra`.

`office.config.json` for a dev instance (generated from the example): `mattermostUrl`
`http://127.0.0.1:<base>`, `forgejoUrl` `http://127.0.0.1:<base+1>`, `tmuxSession`
`office-<name>`, `opencodeBasePort` `<base>+10`, `defaults.opencodeModel` set to the example's
`defaults.helperModel` (the cheap model), `selfManagement.maxAgents` unchanged.

Port base: a block of 100 ports (opencode agent ports count up from `base+10` and are never
reused, also for retired agents). Start from `20000 + (hash(name) % 100) * 100`, probe that
`base`, `base+1`, `base+2` are free on 127.0.0.1, and step by 100 until a free block is found.
`--port-base N` overrides.

Instance slug: `--name`, else a slug of the checkout directory's basename; `[a-z0-9-]`, at most
24 characters. The instance name is `<slug>-<hash6>` as above.

### Library API (`src/lib/infra.ts`, pure parts unit-tested)

```ts
export const DEV_OVERRIDE = 'docker-compose.dev.yml'
/** OFFICE_INSTANCE from infra/.env, or undefined for a normal office. */
export function instanceName(root: string): string | undefined
/** Container name prefix: OFFICE_CONTAINER_PREFIX from infra/.env, default 'agent-office'. */
export function containerPrefix(root: string): string
/** Throws when this office's containers exist but belong to another checkout. */
export function assertStackOwnership(root: string): void
```

```ts
/** Throws when infra/.env marks a dev instance but office.config.json does not match it. */
export function assertInstanceConfig(root: string, cfg: OfficeConfig): void
```

`assertInstanceConfig` runs at `office.ts` startup for every command except `dev init` /
`dev reset` (which repair it): when `OFFICE_INSTANCE` is set, `cfg.tmuxSession` must equal
`office-<name>` and the ports in `cfg.mattermostUrl` / `cfg.forgejoUrl` must equal `MM_PORT` /
`FORGEJO_PORT`; otherwise abort with a message to run `office dev init`. This stops a dev
checkout with a regenerated default config from acting on the live tmux session `office`.

`assertStackOwnership` inspects `<prefix>-mattermost`, `<prefix>-forgejo`, `<prefix>-postgres`
(`docker inspect --format` of the label `com.docker.compose.project.working_dir`). If a
container exists and its working dir, resolved with `realpath`, differs from this checkout's
`infra/`, it throws an error that names the other checkout and says to run `office dev init`
for an isolated dev office. `docker inspect` also sees stopped containers, which is wanted. If
the label's path no longer exists on disk (the checkout was moved or renamed), it returns: that
is the same office at a new path. No container, or Docker not reachable: it returns (the later
compose call reports Docker problems). The label parsing and comparison is a pure function with
unit tests; the `docker inspect` call is injected or thin.

Called before every `docker compose` call that changes state, not only `up`: in `bootstrap()`,
in `ensureInfra()` in `src/cli/office.ts` (which covers `up` and `start`), at the top of
`exportOffice` and `importOffice` in `src/lib/migrate.ts` (they run `compose stop` / `down`
before any `up`), and before every compose call in `dev-cmd.ts`.

Further guards:

- `export`, `import` and `setup` refuse on a dev instance (`instanceName(root)` set): the
  bundle tars `infra/data`, which a named-volume instance does not have, and `setup` hardcodes
  the default ports and `tailscale serve`.
- `shutdown`, `admin-stop` and `export` refuse when `state/office.json` does not exist: an
  uninitialised checkout has the default `tmuxSession: "office"` and would kill the live
  office's windows.

`bootstrap.ts` stops using literal container names: `dockerExec` becomes
`docker compose <composeFileArgs> exec -T [-u user] <service> ...` with service names
`mattermost` / `forgejo`.

### CLI (`office dev …`, new `src/cli/dev-cmd.ts`, wired in `src/cli/office.ts`)

| Command | Behaviour |
|---|---|
| `office dev init [--name n] [--port-base N]` | Create or reuse this checkout's dev instance, then run the normal init (bootstrap + brain). Prints the instance name, chat/tickets URLs, owner username and password location. Idempotent: an existing dev instance keeps its name and ports. |
| `office dev info` | Print instance name, compose project, URLs, tmux session. Exit 1 with a message if this checkout is not a dev instance. |
| `office dev down [--purge]` | Stop this instance's agent sessions and admin daemon, `docker compose down`. With `--purge`: `down -v`, then delete `state/`, `workspaces/`, `brain/`, `office.config.json`, `infra/.env`. |
| `office dev reset` | `dev down --purge` then `dev init` with the same name. |

Safety rules, enforced in code:

- `dev init` refuses when the checkout holds a normal office: `state/office.json` exists and
  `infra/.env` has no `OFFICE_INSTANCE`.
- `dev init` may replace `office.config.json` only when `state/office.json` does not exist
  (the CLI auto-creates the config from the example on any command).
- `dev down`, `dev reset` refuse unless `OFFICE_INSTANCE` is set, and also when the resolved
  container prefix is `agent-office` or the compose project is `infra`. They must never touch a
  normal office.
- Creating a new instance refuses when Docker volumes labelled with that compose project
  already exist (left over from a deleted checkout at the same path); the message gives the
  `docker volume rm` / `dev down --purge` way out.
- `dev-cmd.ts` does not import from `office.ts` (which runs `main()` on import). It takes its
  collaborators (`bootstrap`, `ensureBrain`, `shutdownOffice`, a `run` for docker, a port probe)
  as an injected deps object, the way `group-cmd.ts` takes `GroupDeps`.
- `dev` subcommands must work on a fresh clone (no config, no `infra/.env`).

### Tests

- Unit (`npx vitest run`, default): pure functions only; no Docker.
- Integration (`test/integration/`, `OFFICE_INTEGRATION=1`): runs against this checkout's
  stack. New guard in `beforeAll`: if the checkout is not a dev instance, fail with a message
  telling the reader to run `bin/office dev init`. There is no override: these tests never run
  against a normal office.
- End to end (`test/e2e/agent-loop.test.ts`, `OFFICE_E2E=1`, same dev-instance guard): hire one
  opencode agent on `defaults.helperModel`, DM it as the owner, wait for its reply in chat
  (timeout 240 s), then `retire` it in `afterAll`. Details that are fixed:
  - `cmdHire` is not importable, so the test shells out to `bin/office hire <name> --harness
    opencode --model <helperModel>` and `bin/office retire <name>`.
  - Hire rejects a name that ever existed, retired or not: use a unique name per run
    (`e2e-<base36 time>`).
  - If `OPENCODE_GO_API_KEY` is in the environment, store it first with
    `setSecret(root, 'opencode-go', key, cfg.resourceGroups)` from `src/lib/vault.ts`
    (`office vault set` needs a TTY). Otherwise the machine's own opencode login is used.
  - Assert only that the agent's bot user posted in the DM channel after the owner's message,
    not what it said.
  - The DM and the wait reuse the approach of `scripts/dm.ts` and `scripts/wait-reply.ts`.
  Skipped unless `OFFICE_E2E` is set.


### CI (`.github/workflows/ci.yml`)

- `test` (existing, Node 20 and 22): add `npm run lint`.
- `integration` (new, Node 22): `npm ci`, `bin/office dev init --name ci`,
  `npm run test:integration`, always `bin/office dev down --purge`. On failure, dump
  `docker compose logs` (through `bin/office dev info` for the project name), and in the `e2e`
  job also the tmux pane of the agent and `state/agents/*/mcp.log`.
- `e2e` (new, Node 22): same stack bring-up, install `tmux` and opencode, run
  `npm run test:e2e`. Its steps run only when the `OPENCODE_GO_API_KEY` secret is present
  (job-level `env` plus step-level `if: env.OPENCODE_GO_API_KEY != ''`), so forks and repos
  without the secret pass with a notice.

## Work packages

Four packages with disjoint files, run in parallel. No package runs `docker`, `bin/office`
commands that touch Docker or tmux, or `git commit`; the lead runs the live checks and commits.
Each package must leave `npx tsc --noEmit` and `npx vitest run` green for its own files.

### A. Instance isolation and guard

Files: `infra/docker-compose.yml`, `infra/docker-compose.dev.yml` (new), `infra/.env.example`,
`src/lib/infra.ts`, `src/lib/migrate.ts`, `src/lib/harness/claude.ts`, `src/cli/bootstrap.ts`,
`src/cli/dev-cmd.ts` (new), `src/cli/office.ts`, `src/cli/setup.ts`,
`test/dev-instance.test.ts` (new), and existing tests whose expectations change.

Also in A: the repo-root `CLAUDE.md` is about developing Agentcy and must not be loaded by
hired agents whose cwd is `workspaces/<name>/`. Add `claudeMdExcludes` for `<root>/CLAUDE.md`
to the per-agent settings built in `src/lib/harness/claude.ts`, with a unit test.

`instanceName`, `containerPrefix` and `DEV_OVERRIDE` already exist in `src/lib/infra.ts` (the
lead added them before dispatch so the other packages type-check); keep their signatures.

Implements everything under "Instance model", "Library API" and "CLI". Unit tests cover: name
slugging, port-block selection with an injected "is free" probe, generated `infra/.env` and
config contents, `composeFileArgs` with and without `OFFICE_INSTANCE`, ownership comparison
(same dir, other dir, no container, symlinked path), and each refusal rule.

### B. Integration guard, end-to-end test, CI

Files: `test/integration/platform.test.ts`, `test/e2e/agent-loop.test.ts` (new),
`test/helpers/dev-instance.ts` (new, the shared guard), `.github/workflows/ci.yml`.

Uses only the contract: `instanceName(root)` from `src/lib/infra.ts` (written by A; import it,
do not reimplement), the `office dev` commands, and the npm script names.

### C. Hygiene and docs

Files: `package.json`, `package-lock.json`, `biome.json` (new), `.claude/settings.json` (new),
`scripts/dev-bootstrap.sh` (new), `CLAUDE.md` (new in git; start from the untracked copy in the
main checkout), `AGENTS.md` (new, a short pointer to `CLAUDE.md` for non-Claude coding agents),
`docs/research/{chat-platforms,inspirations,knowledge-fork-merge,sandboxing-browsers}.md`
(copied from the main checkout), `CONTRIBUTING.md`, `README.md` (Tests section and a new
"Developing Agentcy" section), `.gitignore` if needed.

- Biome as a dev dependency. `biome.json`: linter on with the recommended set; any rule that
  fails on the current code is turned off in the config, and the report lists them (no source
  edits in `src/` or `test/`, which belong to A and B). Formatter disabled and no `format`
  script: one accidental run would reformat the tree under two in-flight branches. Ignore `node_modules`, `state`, `workspaces`, `brain`, `infra/data`,
  `coverage`, `.worktrees`.
- `scripts/dev-bootstrap.sh`: runs `npm ci` only when `node_modules` is absent. It never
  reinstalls over an existing `node_modules` (a running office executes `tsx` and the MCP
  servers from it; `npm ci` deletes the directory first), does nothing when `state/office.json`
  exists and `node_modules` is present, and exits immediately when the session's cwd is under
  `workspaces/` (a hired agent's session). When the lockfile is newer than `node_modules` it
  only prints a notice. `.claude/settings.json`: a `SessionStart` hook that runs it, so a new
  worktree or a cloud session is ready to type-check and test.
- Research docs are going into a public repository: remove machine-local paths and report
  anything that looks private instead of committing it.
- `CLAUDE.md`: add the dev-office workflow and the hard rule (never `init/up/start/setup` a
  second checkout without `office dev init`; never touch the live office's agents), the new
  npm scripts, and a pointer to `.claude/skills/`.

## Verification (lead, after the packages land)

1. `npm run check`.
2. `docker compose -f infra/docker-compose.yml config` with the live office's `.env` values
   renders the same container names, ports and bind mounts as on `main`, and
   `docker compose config --hash '*'` computed in the live checkout's `infra/` with the new
   compose file equals the live containers' `com.docker.compose.config-hash` labels, which
   proves an upgrade recreates nothing.
3. In this worktree: `bin/office dev init`; confirm the three live containers are untouched
   (same container ids and start times), the dev stack is on its own ports, and
   `bin/office up` from a scratch clone without `dev init` is refused by the guard.
4. `npm run test:integration` and `npm run test:e2e` against the dev instance.
5. `bin/office dev down --purge`; confirm nothing of the instance remains and the live stack is
   still untouched.
6. Opus review of the full diff; fix findings; push; open the PR; watch CI.
